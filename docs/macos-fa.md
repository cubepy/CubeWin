# وضعیت مک‌اواس — راهنمای فارسی

نسخه انگلیسی و فنی‌تر این سند: [`macos-port.md`](macos-port.md)

---

## خلاصه در یک جمله

برنامه روی مک **باز می‌شود و تونل هم کار می‌کند** — ولی با یک روش دور زدن
ضعیف‌تر، و بدون سه امکانی که به ویندوز گره خورده‌اند.

> این سند قبلاً می‌گفت اتصال روی مک کار نمی‌کند. آن حرف مربوط به قبل از
> اضافه شدن هستهٔ جایگزین است و دیگر درست نیست.

---

## الان روی مک چه کار می‌کند و چه کار نمی‌کند

| بخش | وضعیت روی مک |
|---|---|
| باز شدن برنامه و رابط کاربری | ✅ کار می‌کند |
| افزودن، ویرایش و حذف کانفیگ | ✅ کار می‌کند |
| ورود به حساب کاربری | ✅ کار می‌کند |
| بررسی بروزرسانی | ✅ کار می‌کند |
| تنظیمات پیشرفته، لاگ زنده، ابزارها | ✅ کار می‌کند |
| **اتصال (تونل)** | ✅ کار می‌کند — با روش جایگزین، پایین را بخوانید |
| پروکسی سیستم | ❌ کار نمی‌کند |
| حالت TUN | ❌ کار نمی‌کند |
| درگاه موبایل | ❌ کار نمی‌کند |

آن سه مورد آخر در برنامه **خاکستری و غیرفعال** هستند و اگر ماوس را رویشان
نگه دارید، دلیلش را می‌نویسند. پیام خطای قرمزی در کار نیست — چیزی خراب نشده.

### روش جایگزین یعنی چه؟

روی ویندوز برنامه از **wrong-sequence** استفاده می‌کند: یک بستهٔ جعلی وسط
اتصال تزریق می‌کند. این کار به درایور WinDivert نیاز دارد که فقط روی ویندوز
هست.

روی مک به‌جایش **تکه‌تکه کردن TLS** (TLS fragmentation) اجرا می‌شود: دست‌دادن
اولیه را طوری می‌شکند که فیلترکننده نتواند نام سایت را در آن ببیند. این روش
به هیچ درایوری نیاز ندارد، ولی **ضعیف‌تر** است — روی بعضی از فیلترینگ‌هایی که
wrong-sequence رد می‌کند، ممکن است جواب ندهد.

برنامه خودش تشخیص می‌دهد و در لاگ می‌نویسد کدام هسته فعال است:
`SNI core: fragmentation`.

### چون پروکسی سیستم کار نمی‌کند، ترافیک را دستی وصل کنید

روی ویندوز برنامه خودش پروکسی سیستم را تنظیم می‌کند. روی مک این کار انجام
نمی‌شود، پس بعد از اتصال باید مرورگر یا برنامه‌تان را دستی به این آدرس‌ها
وصل کنید:

```
SOCKS5:  127.0.0.1:20808
HTTP:    127.0.0.1:20809
```

یا از طریق  System Settings → Network → (شبکه فعال) → Details → Proxies
همین مقادیر را وارد کنید. یادتان باشد بعد از قطع اتصال، دستی برشان دارید.

## چطور همین حالا روی مک اجرایش کنید

نیازی به Xcode یا حساب توسعه‌دهنده نیست. فقط پایتون.

### اول نسخه پایتون را چک کنید — مهم است

```bash
python3 --version
```

**باید ۳.۱۰ یا بالاتر باشد.**

اگر نسخه پایین‌تری نشان داد، یا اگر مسیر پایتون داخل `Xcode.app` بود، پایتون
پیش‌فرض مک قدیمی است و کار نمی‌کند. از
[python.org/downloads](https://www.python.org/downloads/) نسخه جدید را نصب
کنید، Terminal را ببندید و دوباره باز کنید.

### دستورات

```bash
# ۱. دریافت کد
git clone https://github.com/cubepy/CubeWin
cd CubeWin

# ۲. نصب کتابخانه‌ها
python3 -m pip install -r requirements.txt

# ۳. دریافت موتورها (Xray و sing-box نسخه مک)
chmod +x install-engine.sh
./install-engine.sh

# ۴. اجرا
python3 main.py
```

پنجره برنامه باز می‌شود. رابط کاربری، کانفیگ‌ها، تنظیمات — همه در دسترس‌اند.

### خطاهای رایج

**`No matching distribution found for pydivert`** — پایتون شما قدیمی است.
بخش بالا را ببینید. آن کتابخانه فقط روی ویندوز لازم است و روی مک اصلاً نصب
نمی‌شود؛ `requirements.txt` این را می‌داند و از رویش رد می‌شود.

**پنجره‌ای درباره «developer tools»** موقع اولین `git` — روی Install بزنید،
صبر کنید تمام شود، بعد دستور را دوباره بزنید.

**خطای permission در مرحله نصب** — به‌جایش این را بزنید:
`python3 -m pip install --user -r requirements.txt`

**`CONFIG FAIL … [Errno 13] Permission denied`** یا اینکه `install-engine.sh`
می‌گوید باینری اجرا نشد — کار Gatekeeper است. هر فایلی که با `curl` دانلود
شود برچسب قرنطینه می‌خورد و مک اجازهٔ اجرایش را نمی‌دهد. این را بزنید:

```bash
xattr -cr bin/
chmod +x bin/xray bin/sing-box
./bin/xray version
```

خط آخر باید چیزی شبیه `Xray 26.3.27 … darwin/arm64` چاپ کند. اگر کرد، مشکل
حل شده. (نسخهٔ جدید `install-engine.sh` خودش این کار را می‌کند؛ این دستور
برای نصب‌های قدیمی‌تر است.)

**`sing-box: No such file or directory`** — مهم نیست. sing-box فقط برای حالت
TUN لازم است که روی مک اصلاً فعال نمی‌شود. تونل بدون آن کار می‌کند.

**اگر خطای دیگری گرفتید**، متن کامل خطا را بفرستید.

### فایل‌های برنامه کجا ذخیره می‌شوند؟

```
~/Library/Application Support/CubeVPN/
```

برای تغییرش، متغیر `CUBEVPN_DATA_DIR` را تنظیم کنید.

## چرا روش قوی‌تر (wrong-sequence) روی مک نیست؟

برنامه روی ویندوز از **WinDivert** استفاده می‌کند: یک درایور که در عمق ویندوز
می‌نشیند، بسته‌های شبکه را می‌بیند و بسته جعلی تزریق می‌کند.

روی مک چنین چیزی وجود ندارد:

1. **اپل راه را بسته.** از macOS 11 به بعد، نوشتن این نوع درایور (kext) عملاً
   ممنوع شده و برای برنامه‌ای که قرار است منتشر شود، بن‌بست است.

2. **جایگزین اپل کار متفاوتی می‌کند.** اسمش `NetworkExtension` است. به شما یک
   کارت شبکه مجازی می‌دهد و بسته‌ها را از آن عبور می‌دهد — ولی اجازه نمی‌دهد
   وسط یک اتصالِ از قبل برقرار، بسته جعلی تزریق کنید. و تکنیک این برنامه
   (wrong-sequence) دقیقاً همین است.

3. **حتی اگر شدنی باشد، مجوز می‌خواهد.** اپل باید جداگانه اجازه استفاده از
   `NetworkExtension` را به حساب توسعه‌دهنده بدهد.

## چقدر از کد قابل استفاده مجدد است؟

خبر خوب: **بیشترش**. حدود ۲۹۰۰ خط بدون هیچ تغییری منتقل می‌شود:

| بخش | خطوط | نیاز به تغییر |
|---|---:|---|
| مدل‌ها و پارس کانفیگ | ۵۵۰ | ندارد |
| ذخیره‌سازی تنظیمات | ۴۸۹ | ندارد |
| پروکسی داخلی | ۵۰۸ | ندارد |
| شبکه و پینگ | ۳۷۷ | ندارد |
| بررسی بروزرسانی | ۳۵۷ | ندارد |
| آیکون‌ها | ۲۷۸ | ندارد |
| حساب کاربری | ۱۸۱ | ندارد |
| ابزارهای TLS | ۱۰۷ | ندارد |

رابط کاربری هم چون با Qt نوشته شده، بومی روی مک اجرا می‌شود.

آنچه باید از صفر نوشته شود: تزریق بسته، کنترل پروکسی سیستم، و درگاه موبایل.

## قدم بعدی چیست؟

به ترتیب اولویت:

**۱. کنترل پروکسی سیستم روی مک.** بزرگ‌ترین آزار روزمره همین است — الان باید
دستی پروکسی را ست کنید. معادلش روی مک `networksetup` است؛ کار سختی نیست، فقط
باید هنگام کرش هم درست برگردانده شود، همان‌طور که نسخهٔ ویندوز می‌کند.

**۲. آزمودن اینکه fragmentation در عمل چقدر جواب می‌دهد.** این را فقط با
استفادهٔ واقعی روی شبکهٔ ایران می‌شود فهمید، نه با تست.

**۳. سؤال بزرگ، اگر روزی fragmentation کافی نبود:**

> آیا تکنیک wrong-sequence اصلاً از طریق `NetworkExtension` قابل پیاده‌سازی
> هست یا نه؟

- اگر **بله** → مک هم می‌تواند همان قدرت ویندوز را داشته باشد.
- اگر **نه** → مک به یک روش دور زدن **کاملاً متفاوت** نیاز دارد.

### برای جواب دادن به سؤال سوم لازم است

- یک مک ✅ (دارید)
- برنامه Xcode (رایگان، از App Store)
- حساب توسعه‌دهنده اپل (سالانه ۹۹ دلار) — برای اینکه اپل مجوز
  `NetworkExtension` را بدهد

### توصیه

با بسته‌بندی و ساخت نسخه نصبی **شروع نکنید**. با یک نمونه آزمایشی کوچک و
دورریختنی شروع کنید که فقط همان یک سؤال را جواب بدهد. اگر جواب منفی بود،
بقیه کار صرفه‌جویی می‌شود.

## چرا هنوز نسخهٔ نصبی مک منتشر نمی‌شود؟

تونل کار می‌کند، ولی هنوز **یک محصول قابل انتشار** نیست:

- پروکسی سیستم دستی است. کاربر عادی حاضر نیست هر بار پروکسی مرورگرش را
  دستی عوض کند.
- fragmentation هنوز روی شبکهٔ واقعی به‌قدر کافی آزموده نشده.
- برای اینکه مک بدون هشدار Gatekeeper اجرا شود، به امضا و notarization اپل
  نیاز است — یعنی حساب توسعه‌دهنده.

پس فعلاً «از روی سورس اجرا می‌شود» درست است و «نسخهٔ نصبی داریم» درست نیست.
اولین قدم برای عوض شدن این وضعیت، مورد ۱ بالاست.
